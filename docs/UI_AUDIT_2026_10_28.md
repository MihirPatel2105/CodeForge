# UI consistency audit — 2026-10-28

## Scope

Reviewed shared primitives and page styles against the current CodeForge design,
then inspected 46 route variants at 1440 × 1000 and 375 × 812. Theme-enabled pages
were also inspected in dark mode. Local UI fixtures supplied account/run data;
unavailable services used the existing error states. This audit did not start
real agent runs or change production data.

| Area | Routes inspected |
| --- | --- |
| Marketing | Home, About, How it works, FAQ, Contact, Privacy, Terms, missing-page recovery |
| Authentication | Login, signup, forgot/reset password, authenticator recovery and review invitation, sign-in alert |
| Workspace | Projects, project detail, profile, settings, password, two-factor, passkeys |
| Execution | Run view, usage, browser tester, publishing, library demo |
| Operations | Overview, runs/detail, hosting, incidents, recovery, users/detail, quality, monitoring, system, audit log |
| Visual experiences | Agent City playground/sample replay and the four existing preview routes |

The route sweep includes loaded and service-error states. The interaction suites
provide deeper coverage of loaded admin data, approval dialogs, enrollment,
publication, recovery, keyboard navigation, pending feedback, and failures.

## Findings and fixes

- Account/security and admin action corners differed from the main workspace.
  Removed page-level radius overrides and defined action/compact geometry in the
  shared button system.
- Action links used independent classes and lift animations. Added `ButtonLink`
  and migrated marketing, demo, recovery, settings, and notification actions to
  the same variants and feedback as submit buttons.
- Fields and focus rings were styled independently by some pages. Shared input
  and textarea classes now use 12px corners, common transition timing, and visible
  normal/invalid keyboard focus.
- Button feedback, selection indicators, and Arc responsive motion used different
  presets. Actions now share one spring, selection uses the shared preset, and
  standard durations/easing come from central tokens.
- Agent City tool corners and theme controls differed from run controls. Unified
  the compact control treatment and kept its light/dark appearance aligned with
  CodeForge.
- Kept semantic run colors, readable code-editor contrast, hero compositions,
  replay controls, and workflow behavior intact. Control density can vary by
  layout; the visual language and interaction rules stay the same.

## Verification

- Production build, TypeScript, lint, and `git diff --check` passed.
- All **235 tests in 48 frontend CI spec files passed** against the production
  build, including the five new cross-page consistency checks.
- The 46-route browser sweep found no JavaScript page errors or horizontal
  overflow at the inspected desktop/mobile widths.
- Screenshot and computed-style evidence is saved locally in
  `output/ui-consistency-before/` and `output/ui-consistency-final/`.
- The shared rules and component choices are documented in [UI_SYSTEM.md](UI_SYSTEM.md).
